# Compiler IDE

Qt6 IDE for the language defined in `grammar/compiler.gals`, wired to the
lexical/syntactic/semantic analyser that GALS generates from that grammar.

## Layout

```
CMakeLists.txt
grammar/
  compiler.gals        grammar source, semantic actions included (edit this)
  gals-output.zip      archive GALS produced; already extracted into src/gals
tools/
  galsgen.py           rebuilds the parser tables after the grammar changes
src/
  main.cpp
  ide/                 Qt front end (main window, code editor, symbol table)
  cli/                 headless front end, used by tests/run_tests.sh
  compiler/            bridge: drives the analyser, maps errors to line/column
  semantic/            symbol table, scopes and the type rules
  gals/                GENERATED by GALS -- except Semantico.{h,cpp}
tests/                 valid sample programs
tests/erros/           programs that must fail, one lexical/syntax error each
tests/semantica/       T3 samples, one per requirement
```

## Build and run

```sh
cmake -S . -B build -G Ninja
cmake --build build
./build/compiler-ide          # the IDE
tests/run_tests.sh            # compile every sample and check the outcome
```

`./build/compiler-cli --table <file>` compiles without the GUI and prints the
diagnostics and the symbol table; that is what the test script drives.

## T3 — semantic analysis

The grammar carries 47 semantic actions (`#1` … `#47`); `Semantico::executeAction`
in `src/gals/Semantico.cpp` implements them, and the header comment there maps
every number to what it does. Nothing is thrown: the actions collect errors and
warnings so one compilation reports every problem it found, which is also the
only way the "declared but never used" check can work — it has no answer until
a scope closes.

| Requirement | Where |
| --- | --- |
| Identifiers in the table with type, modality and scope | actions 4, 6, 8, 9, 46, 47; `src/semantic/symboltable.*` |
| Declared in the scope where they are used, no leaking | `SymbolTable::lookup` walks only the open scopes |
| One declaration per name per scope | `SymbolTable::declare` refuses a name already in the innermost scope |
| Warn about identifiers nobody used | `reportUnused`, run whenever a scope closes |
| Warn about use before initialisation | `markUsed`; a warning, never a rejection |
| A place in the IDE to look at the table | the "Tabela de simbolos" dock (View ▸ Symbol Table, Ctrl+T) |
| Type compatibility in expressions and assignments | the `binary*` helpers and `checkAssignment` |

Modalities are `variavel`, `vetor`, `parametro`, `parametro vetor` and `funcao`;
a procedure is a `funcao` whose type is `void`.

Scopes nest: `global`, then one per subroutine (its parameters and its top level
locals share it, so a local cannot shadow a parameter), then one per `{ }` block.
A vector named without an index is a legal argument for a vector parameter and
an error everywhere else.

Only `int` widens to `float`; every other assignment needs matching types.
Arithmetic takes `int`/`float`, `%` and the bitwise operators take `int`, the
logical operators take `boolean`, and `if`/`while`/`for`/`do..while` conditions
must be `boolean`.

## Regenerating the analyser

Edit `grammar/compiler.gals`, then:

```sh
python3 tools/galsgen.py        # --check reports whether the tables are stale
```

`tools/galsgen.py` rebuilds the SLR tables in `src/gals/Constants.{h,cpp}` and
leaves the scanner tables alone, which is all that changes when only semantic
actions move. It reproduces the tables GALS emitted for the action-free grammar
byte for byte, which is how it was checked. Use GALS itself when the tokens or
the regular definitions change — and then keep `Semantico.h`, `Semantico.cpp`
and `src/semantic/`, which are hand written.

If a semantic action is placed where it would make the grammar ambiguous, the
script refuses to write and names the conflicting state.

## How the IDE talks to the compiler

`Compiler::analyze(source)` in `src/compiler/compiler.cpp` is the only contact
point. It hands the UTF-8 source to `Lexico`, runs `Sintatico::parse`, and
converts `LexicalError` / `SyntacticError` / `SemanticError` — which carry a
byte offset — into the 1-based line and column that `CodeEditor` highlights.
Syntax errors are re-scanned at the failing offset so the message names the
offending lexeme instead of the generic `Erro estado N` from `PARSER_ERROR`.
Once the parse succeeds it also copies the symbol table and the semantic
diagnostics into `CompileResult`, sorted by position, for the IDE to show.
